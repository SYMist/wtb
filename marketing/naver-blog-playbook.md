# 네이버 블로그 플레이북 (Tooly 도달·인지 채널)

Tooly(`tooly.deluxo.co.kr`)로 **검색 유입·브랜드 인지**를 확보하기 위한 네이버 블로그 운영 가이드입니다. 포스팅 5~10개를 기준으로 작성되었습니다.

> ⚠️ **2026-05-30 역할 재정의**: 이 블로그는 Tooly의 **메인 유입 깔때기가 아니라 도달·인지용 보조 채널**입니다. 자연 검색(롱테일 시나리오 SEO)이 본체이고, 블로그는 초기 인지와 약한 트래픽 신호를 보탤 뿐입니다. 홈판 트래픽 = 저의도이므로 Tooly 전환을 과신하지 마세요.

> ⚠️ **"백링크" 오해 교정**: 네이버 블로그의 외부 링크는 거의 전부 **`nofollow`**라, **구글 검색 권위(PageRank)를 Tooly로 넘겨주지 않습니다.** 즉 이 블로그의 Tooly 기여는 *SEO 백링크가 아니라* ① 직접 클릭 유입(referral), ② 브랜드 인지, ③ 사람들이 "Tooly"를 검색·언급하게 만드는 간접 신호입니다. 이 전제로 운영 목표를 잡으세요.

## 1. 목표와 현재 계약

우선순위는 `CURRENT.md`와 이번 실행 지시서에서 가져온다. 현재 청약 정확성·CTA 계측 준비가 한 활성 작업이며, 확인된 배포와 별도 승인 전 블로그를 발행하지 않는다. 과거 주제표는 후보 예시다.

- 최종 경로: 블로그 검색 → Tooly 랜딩 → 계산·비교/다음 행동 → 직접 확인 가능한 광고 수익.
- 고정 CTA 클릭률 10%를 목표로 삼지 않는다. 같은 기간의 관측 가능한 사용자/세션 분모와 최소 표본을 정한 뒤 판독한다.
- 검색 노출, 자동 결과 렌더, 자발적 행동, 광고수익을 구분한다. 체류시간·글 길이는 과업 완료를 대신하지 않는다.
- 검색 알고리즘의 비공개 점수나 특정 분량·이미지 수가 노출을 보장한다는 가정을 제작 의무로 삼지 않는다.
- 독자에게 필요한 직접 답·계산 사례·공식 근거·비교를 제공하고 키워드 반복, 문장 복제, 무의미한 링크 반복은 피한다.

## 2. 주제 선정 원칙

### 좋은 주제 = 아래 4가지 교집합
1. **검색 수요**: 네이버 검색량 있는 질문형 키워드
2. **Tooly 연결성**: Tooly 계산기로 답변 가능
3. **해설 가치**: 계산기만으론 부족한 맥락·예시·팁 제공 필요
4. **롱테일·저경쟁 (★ 신규)**: 거인(은행·언론사·대형 정보블로그)이 얕게 다루거나 무시하는 **구체적 시나리오** 키워드. 광범위 키워드(예: "양도세 계산")는 상위가 이미 포화 → **"1세대 1주택 12억 초과 양도세 얼마"** 처럼 좁히면 스마트블록 진입이 쉽고, 마침 Tooly 깊이 페이지와 1:1로 연결됨

> **원칙**: 헤드 키워드(연봉 실수령액 등)는 진입장벽이 높다. **롱테일 시나리오 1개를 깊게** 쓰는 글이, 광범위 키워드를 얕게 쓰는 글보다 노출·전환·저품질 회피 모두에서 유리하다.

## 3. 원고 구성과 캡처

첫 문단에서 질문에 직접 답하고, 필요한 공식·조건 → 검산한 사례·판단 과정 → 남는 질문 순으로 구성한다. 이 순서는 예시이며 섹션별 최소 분량은 없다. 글 길이·FAQ 수·이미지 수·제목 길이·해시태그 수를 성공 공식으로 고정하지 않는다.

Tooly에서 조건을 바꾸거나 비교할 필요가 생기는 위치에 맥락 있는 CTA를 둔다. 후반부에만 두거나 두 번 반복할 의무는 없다. 본문과 CTA의 비율도 고정하지 않는다.

캡처는 설명 목적이 있을 때만 넣는다. 입력·결과·세부 계산·비교 중 필요한 실제 화면을 선택하고, 설명과 가까운 곳에 `📸 [스샷 N] (화면·입력·설명 목적) — 여기 삽입`을 표시한다. 숫자가 보이고 개인정보가 없는 예시를 사용한다. 타인의 이미지를 무단 복제하지 않는다.

## 4. 작성·발행 준비 체크

- [ ] 제목과 첫 문단에 핵심 상황·조건·얻을 답이 드러나며 실제 잘림을 확인했다.
- [ ] 사이트 문장을 복제하지 않고 사례·판단 과정·흔한 실수·비교 중 독자적 가치를 제공한다.
- [ ] 공식 출처·기준일·개정 사항과 계산 수치를 검증했다. 페이지 로직만을 독립 정답으로 삼지 않는다.
- [ ] 실제값·예시값·근사값을 구분했다. 필요한 표·캡처·FAQ만 사용한다.
- [ ] 실제 경험은 사용자 제공 사실에만 근거한다. 없으면 사례로 설명한다.
- [ ] CTA 목적지·딥링크 입력·결과·UTM을 확인했다. 단축 URL과 같은 링크의 무의미한 반복을 피한다.
- [ ] 키워드를 억지로 반복하지 않고, 해시태그는 주제와 관련된 것만 사용한다.
- [ ] 완성 원고 경로·남은 캡처·발행 승인 상태·전환 이벤트·분모를 발행 메모에 남겼다.

## 5. 발행과 판정 시계

발행 빈도·요일·시간을 고정하지 않는다. CURRENT의 선행 조건과 사용자 승인을 충족한 완성 원고만 발행한다. 스킬이나 이 가이드는 발행·외부 공유·댓글·계정 변경의 승인이 아니다.

T0=실제 승인 발행일. T0 직후 링크·랜딩·이벤트 확인, T0+14 중간 판독, 유효 계측 이후 동일 28~30일 창의 충분한 표본에서 검색·수익 판정을 한다. 기존 CPI 2026-09-28 및 청약 검색 2026-10-03 관찰을 새 콘텐츠 실험으로 오염시키지 않는다.

## 6. 측정과 기록

블로그 외부 링크에는 `utm_source=naver_blog&utm_medium=referral&utm_campaign=<고정 slug>&utm_content=<링크 위치>`를 쓴다. 기존 입력 쿼리를 보존하며, Tooly 내부 링크에 새 UTM을 붙여 획득 출처를 재분류하지 않는다.

단계별로 출처·관측일·대상 기간·사용자/세션/클릭 분모를 남긴다. 실제 outbound 자료가 없으면 블로그 링크 클릭은 확인 불가이며 Tooly 랜딩과 동일시하지 않는다. campaign 수익이 없으면 사이트 총수익을 글별로 배분하지 않는다. 기간과 분모가 다른 수치로 전환율을 만들지 않는다.

`subscription_cancel_run`은 default/query 결과 마운트다. query는 자동 딥링크와 자발적 제출을 구분하지 못하므로 자발적 과업 완료로 읽지 않는다. `cta_click`은 명시 클릭이며 page·target·position으로 구분한다. dataLayer 큐, collect 전송, GA4 서버 수신은 별도 증거로 확인하고 테스트 이벤트를 실제 성과에서 제외한다.

노출·CTA 0이면 계측·유통·분모부터 진단한다. 결측은 0이 아니다. 코드와 실행 결과는 Tooly에 기록하고 Avatar에는 검증 증거·위험·다음 결정을 바꿀 사실을 반환한다. Avatar 정본은 수정하지 않는다.

## 7. 경험·사례의 진실성

사용자가 제공한 실제 경험이 있을 때만 구체적 상황·행동·결과를 1인칭으로 쓴다. 없으면 검증된 가상 사례임을 밝힌다. 경험담, 감정, 실패담을 필수 섹션으로 채우거나 placeholder를 실제 경험처럼 발행하지 않는다. 아래 과거 샘플은 톤 참고용이며 사실·수치 검증 없이 재사용하지 않는다.

## 8. 독자 가치 확인

분량을 늘리거나 AI 탐지를 피하는 표현을 넣는 대신, 독자가 답을 얻고 자신의 조건을 판단할 수 있는지 확인한다. 수치·전제·출처가 정확하고 이해하기 쉬운 문장으로 쓴다. 과장·비방·낚시성 제목은 피한다.

## 9. 중복·노출 문제 판독

기존 글과 중복 여부는 해당 주제·대상 URL 범위에서 확인한다. 동일한 사이트 문장과 구조의 기계적 복제는 피한다. 검색 누락이나 유입 감소만으로 원인을 링크 개수·AI·발행 빈도로 단정하지 않는다. 실제 노출·기간·색인/계측 상태를 확보해 경쟁 가설을 비교하고, 추가 수리나 발행은 현재 계약 안에서 결정한다.
