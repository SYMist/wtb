# 네이버 블로그 초안 작성 (Tooly)

블로그 자체로 독자의 질문을 해결하고, 실제 계산·비교가 필요한 순간 Tooly로 연결한다. 초안·검산·캡처 준비까지 수행하며 사용자 승인 전 발행하지 않는다.

## 필요한 입력만 읽기

1. `CURRENT.md`와 사용자가 지정한 검색 시나리오·대상 URL·범위.
2. `marketing/naver-blog-playbook.md`의 해당 작업 절. 연결 페이지의 기능·계산 로직과 공식 근거를 확인한다.
3. `AVATAR_ROOT`가 제공된 경우 `$AVATAR_ROOT/wiki/portfolio/templates/tooly.md`의 **§7 네이버 블로그 원고 요청**. 전환 판독은 **§8**, 이벤트 검증은 **§6**만 추가한다. 소유권·승인 경계가 필요하면 `$AVATAR_ROOT/wiki/portfolio/operating-loop.md`의 **§소유권과 승인**만 읽는다. `AVATAR_ROOT`가 없거나 파일이 없으면 그 결측을 반환하며 Avatar 자료를 복제하지 않는다.

전체 Avatar·플레이북·기존 원고를 필독으로 삼지 않는다. 과거 양도세 원고는 필요한 톤·중복 비교에만 쓰며 현재 우선순위로 승격하지 않는다. 현재 계약과 충돌하면 이 입력 계약을 따른다.

## 작성과 검증

- 검색 의도와 Tooly 기능이 일치하는 한 시나리오를 잡는다. 필수 키워드나 대상 URL을 현재 입력에서 알 수 없을 때만 묻는다. 글의 형식은 독자에게 필요한 사례·판단 과정·흔한 실수·비교로 정한다.
- 제목은 조건과 얻을 답을 드러내고 실제 잘림을 확인한다. 첫 문단에서 직접 답을 준다. 소제목·FAQ·표·이미지·해시태그·분량은 설명에 필요한 만큼만 쓴다.
- 금융 수치는 공식 출처·기준일·개정 내용과 계산 로직을 함께 검증한다. 딥링크 입력과 결과를 검산하고 실제값·예시·근사를 구분한다. 사이트 문장의 복제·기계적 요약은 피한다.
- 실제 경험은 사용자 제공 사실만 사용한다. 없으면 검증된 사례로 설명하며 1인칭 경험·감정이나 경험담 placeholder를 억지로 채우지 않는다.
- 필요한 캡처에만 `📸 [스샷 N] (실제 화면·입력·설명 목적) — 여기 삽입` 마커를 둔다. 개인정보 없는 예시 입력을 사용한다.
- CTA는 독자가 숫자를 바꾸거나 비교할 필요가 생기는 순간, 이유가 드러나는 텍스트 링크로 연결한다. 링크 수·본문 후반 위치·CTA 비율을 고정하지 않는다.
- 블로그 외부 링크: `utm_source=naver_blog&utm_medium=referral&utm_campaign=<고정 slug>&utm_content=<링크 위치>`. 기존 쿼리에는 `&`로 붙이고 목적지·입력·결과를 확인한다. Tooly 내부 링크에는 UTM을 새로 붙이지 않는다.

## 산출과 기록 경계

`marketing/naver-post-<slug>.md`에 원고와 작성자용 발행 메모를 둔다. 메모에는 검색 시나리오, 독자적 가치, 실제 URL·기능, 공식 근거·검산, 필요한 캡처, CTA 위치·UTM, 정의한 이벤트·성공 분모, 승인 상태를 남긴다. 해시태그는 주제와 관련된 것만 쓴다.

T0는 실제 승인 발행일이다. 직후 링크·랜딩·이벤트 확인, T0+14 중간 판독, 충분한 동일 기간의 검색·수익 판정을 구분한다. 계측 구현이나 CTA 0만으로 성공·수요 실패를 선언하지 않는다. `subscription_cancel_run`의 query 마운트는 자동 딥링크와 직접 제출을 구분하지 못한다.

Avatar 정본은 수정하지 않는다. Tooly 실행 문서와 원고에 결과를 남기고, Avatar에는 변경·검증 증거·위험·다음 결정을 바꿀 사실을 반환한다. 발행·계정 설정·외부 공유는 이 스킬 실행만으로 승인되지 않는다.
