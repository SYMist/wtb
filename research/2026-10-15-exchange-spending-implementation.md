# 내 금액·수수료를 넣는 해외 지출 비교 — 구현·검증

상태: 구현·최종 production 화면 검증 완료. 후속 사용자 승인으로 원격 반영·자동 배포 확인 진행 중.

## 범위와 기준

- 기존 `/data/exchange/compare`만 확장했다. 기준 소스는 최신 원격 `main`과 일치한 `426da113f35218186879f3f9855bd84a99ae33d4`이며 작업 브랜치는 `feat/exchange-spending-compare`다.
- 지정된 `research/2026-10-15-feature-ideation-top5.md`는 이 기준 소스에 없다. 사용자 지시에 따라 대화에서 전달된 구현 계약을 근거로 삼았다.
- 사용자가 이번 구현에 한해 오래된 매니페스트의 편집 제한 예외를 명시 승인했다. 매니페스트를 정상 검증했다고 보고하지 않으며, 이번 예외를 다음 환경 이동에 적용하지 않는다.
- 저장소의 작업 세션 지정은 GPT-6 Luna/high다. 현재 세션의 모델·effort를 확인하거나 변경하는 인터페이스가 없어 실제 적용은 미확인/미변경이다.

## 실제 사용자 흐름

1. 기존 통화·시작월·종료월을 조회하거나 프리셋을 선택한다. 기존 딥링크·통화별 canonical·ECOS 월평균 SSR 본문은 유지한다.
2. ‘비교할 외화 금액’에 양수를 입력하면 선택한 두 월의 환산액과 `종료월 − 시작월` 차액이 즉시 바뀐다. 기본값은 기존과 같은 외화 100단위다. 고정 원화 100만원 구매력 카드는 별도로 유지하며 개인 입력과 독립임을 표시한다.
3. 아래 ‘실제 견적 비교’에서 같은 통화·금액에 대해 직접 확인한 A/B 적용환율을 입력한다. 역사 월평균을 자동 입력하지 않는다.
4. 수수료 별도에서는 비율 수수료(기본 환산액에 붙는 추가 비용률)와 고정 원화 수수료를 입력한다. 비율 수수료가 은행의 환율 우대율과 다름을 입력 도움말에 연결했다.
5. 수수료 포함 최종견적에서는 모든 비용이 반영된 적용환율을 입력한다. 추가 수수료 필드를 비활성화하고 계산에서도 무시한다. 모드를 어느 방향으로 바꾸든 비율·고정 수수료는 0으로 초기화하며 적용환율은 유지한다.
6. 결과 요약에서 A 총비용·B 총비용·`B − A` 차액을 함께 확인한다. 양수는 B가 더 비싸다는 뜻이다.

통화 또는 실제 비교 기간이 바뀌면 컴포넌트 키를 바꿔 외화 금액은 100, 견적 환율은 빈 값, 수수료는 0, 모드는 별도로 초기화한다. GET 조회와 새로고침도 새 화면을 만들므로 초기화한다. 통화·기간이 바뀌는 프리셋 이동에서도 같은 동작을 확인했다. 같은 화면 내에서 외화 금액만 바꾸면 A/B 적용환율·수수료는 유지한 채 다시 계산한다.

## 계산·표시

기본 환산액 = 외화 금액 × 적용환율 ÷ 고시 단위. 별도 총비용 = 기본 환산액 × (1 + 비율 수수료/100) + 고정 원화 수수료. JPY 고시 단위는 100엔, USD·EUR·CNY는 기존과 같은 1단위다.

| 입력 | 기대 결과와 확인값 |
| --- | --- |
| EUR 3,000 × 1,550 | 4,650,000원 |
| EUR 3,000 × 1,600 | 4,800,000원, B − A = +150,000원 |
| 4,650,000원에 1% + 5,000원 | 4,701,500원, B가 4,800,000원이면 차액 +98,500원 |
| JPY 100,000 × 900원/100엔 | 900,000원 |
| 포함 모드, 적용환율 1,550, 이전 추가 수수료 존재 | 4,650,000원, 중복 가산 없음 |
| 외화 1.25 × 환율 2.345, 0.5% + 0.125원 | 내부 총비용 3.07090625원, 표시 3.07원 |

중간값을 반올림하지 않고, 기존 역사 카드와 동일하게 원화 표시만 소수 둘째 자리까지 반올림한다. 차액도 반올림 전 값끼리 뺀다. 반올림 후 부호 있는 0은 표시하지 않는다. 빈 값·문자·음수·잘못된 소수·0인 금액/환율은 결과를 숨기고 입력 안내를 표시한다. 수수료는 0을 허용하지만 빈 값을 0으로 바꾸지 않는다. 쉼표·지수 표기를 받지 않으며 계산값의 오버플로·언더플로 또는 안전한 수치 범위를 넘는 값은 결과를 표시하지 않는다.

## 개인정보·공유·계측

- 개인 입력은 클라이언트 컴포넌트 메모리에만 둔다. 저장소·서버 요청·검색 파라미터·이벤트에 기록하지 않는다.
- 개인 입력에는 GET 필드 `name`을 주지 않고 기존 추적 폼 밖에 배치했다. 신규 이벤트는 추가하지 않았다.
- 기존 `compare_form_submit`은 유효한 역사 조회 제출, `compare_preset_select`는 역사 프리셋 클릭이라는 의미와 payload를 유지한다. 개인 입력 편집과 모드 전환은 이 이벤트를 만들지 않는다. 기존 자동 렌더 `compare_run`도 바꾸지 않았다.
- 기존 비교 페이지에는 별도 공유 버튼이 없고 조회 URL·프리셋 링크가 공유 경로다. 개인 입력은 공유되지 않고 통화·기간만 공유된다는 안내를 표시했다. 메타데이터도 역사 데이터만 사용한다.
- 로컬 production 브라우저에서 고유한 소수 입력 4개를 사용해 URL·페이지 링크·모든 탐색 요청·gtag 큐 payload에서 원문이 없는지 확인했다. private input을 편집할 때 새 분석 이벤트가 없는 것도 확인했다.
- QA의 외부 스크립트 요청은 로컬에서 빈 응답으로 대체했다. 운영 GA4 서버 수신은 검증하지 않았고, 이번 QA를 운영 성과·수요·전환·수익으로 해석하지 않는다.

- `npm run test:analytics`, `npm run test:base-rate-month`: 통과.
- `npm run lint`: 오류·경고 없음. `npx --no-install tsc --noEmit`: 통과. 최초 별도 타입 검사의 이전 개발 경로 충돌은 Git 제외 `.next/dev` 캐시를 `/tmp/tooly-stale-next-dev-20261015`로 보존·분리해 해결했다.
- `npm run build`: 통과. `npm run build:cf`: 통과, `.open-next/worker.js` 생성 확인. 두 빌드 모두 기존 Google 폰트 접근 경고를 포함한 종료 코드 0이다.
- Chromium production 서버 390×844에서 금액·견적 입력, 비활성 수수료, 결과·차액, 통화·기간·프리셋·새로고침 초기화, 무효 역사 조회의 이벤트 억제를 확인했다. 수평 넘침과 브라우저 런타임 오류는 없었다.
- 소수 키보드 힌트(`inputMode=decimal`)·타이핑·390×480으로 줄인 화면의 포커스와 스크롤을 확인했다. 실제 iOS/Android 소프트웨어 키보드·IME는 실기기 미검증이다.
- USD·EUR·JPY·CNY 모두 로컬 HTTP 200, 통화별 기존 canonical, 실제 역사 환산값·연도별 표·출처·FAQ의 JavaScript 없는 SSR 본문을 확인했다.
- 이번 세션의 QA 스크립트·JSON payload·화면·Cloudflare 빌드 로그: `/workspace/artifacts/exchange-spending/`. 앱 필수 자산이 아닌 Git 미추적 검증 산출물이다.

## 남은 제약·배포

실시간 은행 환율·우대율·상품 API는 추가하지 않았다. 최종견적은 사용자가 확인한 환율과 비용을 가정한 계산이며, 실제 결제사의 청구·반올림 규칙에 따른 금액 차이는 남는다. 역사 카드 옆에 월평균이며 실제 결제금액이 아니라는 안내를 둔다. 미래 환율 예측·환전 시점 추천은 제공하지 않는다.

기존 공유 이미지 생성 과정의 `fonts.googleapis.com` 동적 폰트 다운로드는 이번에도 `EAI_AGAIN` 경고가 발생했다. 해당 접근 제한은 이번 금융 기능 범위 밖이며 빌드 종료 상태와 별도로 기록한다.

초기 구현 완료 시에는 사용자 지시에 따라 배포·원격 push를 하지 않았다. 이후 사용자의 배포·원격 push 진행 요청에 따라 기존 `main` push 기반 Cloudflare 자동 배포를 진행한다. 현재 환경은 Wrangler 미인증이므로 수동 배포를 실행하지 않는다. 이번 기능은 10/05 개선의 사업 성과와 분리하고 2026-10-19 KST 이후 재관찰 일정은 유지한다.
